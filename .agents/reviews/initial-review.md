# Coordinator preliminary review (while workers are writing)

This is not a final assessment; recheck final files before assigning fixes.

1. `src/mcp/worker.rs` currently records `session_started` but checks `last_activity.elapsed()` against SESSION_LIFETIME. The spec requires a total session wall-clock budget, not idle timeout. Frequent requests must not extend it. Track only successful open/close responses, not names before Runtime validation. Add clock-injected or short-duration tests that prove requests don't reset deadline and an invalid close doesn't erase a live session's timer.
2. Review cleanup join paths: `Worker::shutdown` joins indefinitely; if backend call hangs, close must not misleadingly report stopped or hang all diagnostics forever. Need bounded control acknowledgement and explicit fault/unknown semantics; don't promise preempting arbitrary OS calls.
3. Input `Text` is an atomic Backend event but may take a long time for large strings. Need validate actual platform behavior and avoid claiming all input can stop within 1s unless text path is bounded/chunked with cancellation checks.
4. Black-box source denial evidence must apply to final external Claude and MCP child processes, not merely one negative cat probe. GUI itself can be an indirect source channel; acceptance artifacts/traces must show no source window content or alternate shell/API path.

5. CRITICAL native input review: current `src/backend/desktop.rs` negates both scroll axes on the assertion Enigo is opposite. Installed Enigo 0.3 lib.rs lines 336–338 explicitly defines positive=down/right, and win/win_impl.rs negates vertical before sending WHEEL but not horizontal. Runtime contract is positive down/right, so backend should pass x/y unchanged. Add regression tests of translation; do not repeat original prototype's inverted scrolling.
6. CRITICAL held-state review: `inject(Release)` removes HeldItem BEFORE calling platform release; `release_all` drains all then forgets failures. This means a failed release can disappear from tracking and a later cleanup falsely returns success. Remove only after success, retain failures for retry, and use injectable low-level dispatch to test. Drop is best-effort but not a reason to report explicit cleanup success.
7. QA `tests/runtime_contract.rs` currently >1600 lines. Split into modules/support under tests/contract/ with a small entrypoint. Avoid a 1000-click registry-bound test incurring 1000 settle sleeps; introduce controllable clock/timing configuration in test seams while preserving production defaults, or test registry data structure independently plus one integrated bound check.

8. Native macOS capture currently uses `screencapture -D <CGDirectDisplayID> ... -` and assumes stdout PNG. Local `man screencapture` says -D takes 1=main,2=secondary (display ordinal, not CGDirectDisplayID), and output arguments are filenames; no stdout '-' contract is documented. Use existing screenshots capture or a verified CoreGraphics memory capture. Do not introduce a subprocess that might create a literal '-' file or hang. Permission preflight is fine but must not substitute for actual capture proof.
9. A worker temporarily added `pub mod backend` to src/lib.rs despite manifest/lib ownership. Integration is not failed solely by this, but avoid conflicting edits. Core remains final owner, other agents must document any out-of-scope edit.

10. CRITICAL hotkey FFI: macOS `arm` currently passes `Box<Arc<AtomicBool>>` pointer as user_info but callback casts to `*const AtomicBool`. This is a mismatched allocation/pointee type and can corrupt Arc data instead of setting cancellation. Use consistent pointer ownership/type, retain lifetime, test callback flag behavior without real events, and ensure raw pointer capture is Send-safe. Also free registrations/thread resources on shutdown; don't accumulate callbacks on TCP reconnect.
11. Need metadata-only durable-in-session result retention: session.rs currently caps result cache at 256 but permits 1000 registered requests. Older request IDs must remain queryable for their input outcome, even when images evicted. Do not turn a definitely dispatched old result into unknown merely because images were evicted, and never repeat input.

12. Worker ran ignored `live_backend_capture_only` despite instruction to defer real capture. It did NOT capture: DesktopBackend::new returned no_display. Worse, test returns normally on construction failure, so cargo reports pass without real backend validation. Replace with explicit failing/structured skipped diagnostic (not a passing acceptance test). Do not count that run as capture proof. Investigate no_display before blaming TCC.

13. BLACK-BOX ISOLATION P1: run-blackbox-claude.sh currently passes --allowedTools only. This is an auto-approval list, NOT an available-tool denylist. Must add --tools '' plus strict MCP, disable skills and hooks per invocation, replace/inject clean task instructions, audit initial actual tool inventory and every call. No bypassPermissions. A source-free cwd alone doesn't suppress all inherited user/plugin memory; document/restrict startup context and rely on OS denial + observed tool inventory. Interactive mode currently doesn't even send TASK_TEXT unless --print, so ensure task instructions are always supplied.
14. RELEASE SAFETY P1: package-release.sh does `rm -rf "$RELEASE_DIR"` after a lexical path-prefix check. Must reject root/home/repo/ancestor/symlink-resolved aliases and arbitrary existing user dirs; use new mktemp release dir or refuse existing dir unless a tool-owned marker validated. Generate manifest AFTER RELEASE.json. Don't assume cargo --profile dev output is target/dev (actual target/debug). Paths containing quotes must be JSON-escaped.
15. Windows launch needs owner of selected explorer rather than assuming SSH env user equals console user, positive console active-session selection, per-test PID/task identity (don't match every computer-host process), persistent diagnostic logs, and cleanup limited to own task/process. Never stop unrelated Host/user apps. Validate token file ACL; do not put secrets in command line or output.

16. DESKTOP EXCLUSION P1: lock.rs Drop unlocks then unlinks rendezvous file. Race: another process acquires old inode after unlock, first unlinks it, third creates new inode and acquires second lock. Never unlink a live rendezvous lock path; keep stable file. Also lock scope derived from mutable USER/USERNAME/TMPDIR can allow two Hosts on same desktop with distinct lock paths. Use native user/session identity and stable rendezvous or Windows Local\\ named mutex; test contention across processes and after release without inode replacement race. Avoid following attacker-controlled symlinks and validate permissions for stable lock dir.

17. MEMORY P1: session.store_observation clears last_observation on budget overflow then immediately assigns `current_observation.take()` back into it, defeating the check. StepRecord also clones Observation/PNG into result cache, which isn't counted in image_bytes. Need single-accounted shared image store or strip old result images while retaining metadata, and tests that exercise aggregate image budget. Limit encoded capture allocation BEFORE full decode too.
18. PRECISE OUTCOME: if the first backend.inject errors, it may have partially applied side effects; reporting Partial is acceptable only if documented as possible, but completed event range cannot imply no effect. Get-step/replay must preserve original known metadata after PNG eviction.
19. MAX HOLD/TEXT CANCEL: a text action of 4096 chars maps to one uninterruptible native text() call; chunk into bounded native calls with cancellation/deadline checks if claiming 1s cooperative stop. Test cancellation between chunks using fake backend, not just a pre-set flag.

20. TCP authentication claims wall-clock timeout but sets socket timeout to 5s for every byte read; slow clients can extend indefinitely. Enforce an absolute auth deadline and max token length, never log token; test slow partial auth with short injected budget. Keep token format consistent with bridge (currently raw newline token, not JSON as original planning text suggested; update contract or implementation explicitly).
21. Output bound: max 4096x4096 PNG may exceed MCP frame/model image limits although input line cap is 16MiB. Ensure encoded output has a documented byte budget and tool error on oversized image; don't retain unbounded serialized response buffers or lose already-dispatched state when output image too large.
