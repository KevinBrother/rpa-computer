# Windows explicit text paste

Approved direction: user approved a host-owned clipboard paste path on 2026-10-13. Native injection must not silently fall back or be certified by paste results.

## Public contract
`text_input` accepts `method: "native" | "paste"`, default `native`. `paste` is initially Windows-only, is opt-in, and replaces the shared system clipboard with the requested Unicode text. It leaves that text on the clipboard: no timer-based restore (a shortcut being queued does not acknowledge that an application has consumed clipboard data). Never read, log, or attempt to restore the user's previous rich clipboard formats. Tools and README must disclose overwrite/persistence and recommend paste for IME-sensitive controls. Never silently retry, fall back, or claim target text correctness from event dispatch.

`paste` preserves tabs and text line breaks as clipboard data; no Enter/Tab events. Normalize CR/LF line endings to Windows CRLF for CF_UNICODETEXT, preserve all other Unicode scalars. Reject NUL, forbidden C0/DEL and >4096 scalars before any effect; empty input is a no-op. Native behavior is unchanged, including its independent tests and raw native-input library.

## Implementation boundary
Host/backend owns clipboard code; no change to rpa-native-input's native-only contract. Internal Action::TextPaste / PlanEvent::TextPaste / InputEvent::TextPaste represents one bounded transaction. Windows clipboard preparation uses official windows-rs bindings, movable UTF-16 allocation, a real owned invisible HWND, RAII memory/clipboard/window cleanup, no clipboard-content logging. The hidden owner persists through receipt verification and is explicitly destroyed before chord dispatch. Clipboard open fails immediately when busy (no uninterruptible retry loop).

Reject outstanding session-held input and externally held Ctrl/Shift/Alt/Win/V before clipboard modification. Capture the foreground window and focused control. Keep the owned hidden HWND alive across clipboard finalization; after CloseClipboard, reopen and require that HWND still owns the clipboard before bounded readback of only the text this operation published. Require exact UTF-16 payload and capture the finalized sequence under the clipboard lock, then verify the sequence after close and immediately before emitting Ctrl+V. Never adopt an arbitrary post-close sequence or read a foreign owner’s data. Do not change focus or input method. Chord presses/releases go through BackendCore held-state accounting. Release only injected/attempted owned keys on partial failure using existing cleanup. Cancellation before transaction emits no effects; cancellation after its atomic boundary cannot undo queued paste. Report errors conservatively with clipboard modification explained; Windows API failure after EmptyClipboard may leave clipboard empty. Concurrent user input cannot be made atomic with SendInput; document best-effort race guards and serialized desktop ownership.
