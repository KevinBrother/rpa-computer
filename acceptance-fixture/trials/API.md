# Windows first-trial accounting — frozen Stage A contract

Stage A exports only `build_manifest(campaign_id, mode="glm")` and
`summarize(manifest, records)` from this directory's `__init__.py`.
Both explicitly raise `NotImplementedError`. No CLI/GUI runner is implemented.
All following semantics are requirements for Stage B, not current capabilities.
`canonical-fixture.json` is independently authored coordinator-only test data,
not generated by either API and not runtime evidence. Do not publish it to GUI agents.

## Canonical plan

Return a JSON-compatible dict with exactly the keys and nested shapes in
`canonical-fixture.json`. `schema=windows-first-trials-v1`, `platform=windows`.
Campaign is a canonical lowercase hyphenated UUID string; reject other types and
noncanonical spellings with ValueError. Mode is exactly `glm` or `deterministic`;
required_model is `glm-5.3-flash` or null, respectively. All other values are fixed.
No times/random IDs/environment-dependent fields. Calls return fresh objects.

Suite rounds (in slot/group order): pointer 4, multiclick 1, drag 1, scroll 2,
keyboard 3, known-input 1. Each group has trials 1..10, so 12 groups / 120 slots,
60 distinct semantic cases. 95 eligible slots: move12, click25, drag10, scroll14,
text_input10, key_chord12, key_hold12. The other 25 remain in the denominator.
No outcome-driven deletion, eleventh round, or quota adaptation.
Quota is 10 per basic action, NOT per button×count×direction combination.

IDs use UUIDv5 with campaign UUID as namespace and UTF-8 names
`run:{suite}:{round_index}` and `slot:{suite}:{round_index}:{case_id}`.
Round index is 1-based; source trial is 1..10, independent of round index.
Group runtime_run_id and slot runtime remain null, binding_state needs_preflight.
Never infer/forge actual run/session/nonce identities from plan IDs.

Each slot preserves suite, case_id, trial, action (one of seven kinds or null),
classification (`eligible`, `coverage_only`, `blocked`, `rejected`, `zero`),
eligible bool, exact variant, payload (known-input only; otherwise null), and
native_text_policy (known-09 only; otherwise null). Fixed fixture defines exact
variants/classification. keyboard01/02/07/08 are holds, 03..06 chords; 09 is
coverage_only. keyboard02's Enter+Tab sequence counts at most one hold slot.
No key_press action exists. Focus, Check, Next, observation are not target inputs.
Multiclick06..09 and scroll08 are coverage_only; pointer09 blocked; scroll09 zero.
Known payloads preserve NBSP, NFD, non-BMP, tabs, and decoded CRLF. known09 uses
windows-winforms-known09-crlf-v1: native expected is CRLF, not generic LF
normalization. No oracle claim is made by this accounting API.

`sources` is sorted by relative path, exactly the nine existing catalog/policy/task
references in the fixture, each with SHA256 of raw file bytes. Known-input currently
references Cases.cs and NativeTextPolicy.cs (new safe task is Stage B).
`plan_digest` is lowercase SHA256 of UTF-8 JSON of the whole manifest excluding
plan_digest, ensure_ascii=True, sort_keys=True, separators=(",",":"), allow_nan=False.
Summary regenerates the canonical content for campaign/mode, including source
hashes, and requires full equality plus digest equality. Any source drift, edited
threshold/eligible/IDs, missing/duplicate/extra slots, changed schema/mode/platform,
or extra manifest keys raises ValueError. A digest recomputed over tampering is
not an authorization. Neither API modifies its inputs/files.

## Bounds and records

Only plain JSON types: dict/list/str/int/bool/null; no tuples, custom objects,
floats (including nonfinite), cycles, surrogates, or non-string keys.
Limits: manifest <= 1 MiB canonical JSON bytes; records <= 8 MiB canonical JSON
bytes; <= 1200 records (120 first + bounded retries), nesting <= 8 containers;
strings <= 4096 Unicode code points; IDs <=128 ASCII characters; evidence path
<=1024 characters; <=16 evidence refs and <=16 target_calls per record.
All integer fields require type int, never bool; attempt_index 1..10, trial 1..10.
Errors in shapes/types/limits and unknown record keys raise ValueError; no skips,
partial salvage, or missing environment as pass. Summary accepts parsed objects;
future CLI MUST reject duplicate JSON keys, nonfinite literals, truncation and
malformed JSON before invoking API (not a Stage A CLI).

Every record has EXACTLY these keys:
- schema: `windows-first-trial-record-v1`
- record_id, campaign_id, plan_digest, slot_id, plan_run_id
- mode, platform, suite, case_id, trial, attempt_index
- model: required GLM label, or null for deterministic
- runtime: exactly run_id, session_id, nonce (nonempty ASCII IDs), trial (int)
- action: one of the seven kinds (or null only for blocked); mismatch to the
  planned kind is a noncandidate claim, not a schema error. state:
  matched / failed / rejected / zero / blocked / unknown
- target_calls: nonempty list of dicts with exactly tool_call_id, request_id,
  observation_id (nonempty ASCII IDs); blocked may instead use an empty list
- evidence_refs: list of dicts with exactly path (relative, no `..`/absolute),
  sha256 (64 lowercase hex), kind (trace / screenshot / oracle / transcript)

IDs are supplied claims, not proof that linked files exist or are authentic.
Record binding must match campaign/digest/slot/run/mode/platform/model/suite/case/
source trial and runtime trial; malformed/mismatched submissions raise ValueError.
Nonempty unique runtime run_id per planned run (shared across that group's slots),
with consistent session_id and unique nonce per slot. Different groups cannot reuse
runtime run_id or session_id. Retries of a slot retain runtime identity; inconsistent group or retry runtime
identity conflicts all involved slots. Reusing
runtime (run_id,session_id,nonce,trial), tool_call_id or request_id across different
slots is a conflict; observation_id alone may be shared and is not an input call.
Record IDs, or (slot_id,attempt_index), with different contents are conflicts.
Exact duplicate records deduplicate (diagnostic, never extra candidates).
Conflict handling is order-independent: ALL involved slots excluded, not first wins.

## Summary shape

Return dict with exactly: schema (`windows-first-trial-summary-v1`), campaign_id,
plan_digest, mode, platform, planned_slot_count (120), semantic_case_count (60),
run_group_count (12), reported_first_matches (int), candidate_count_met (bool),
gui_verified (false), action_trial_gate_satisfied (false), by_action, by_variant,
slots, duplicates, conflicts, evidence_status (`supplied_claims_only`),
independent_review_required, coverage_limitations.
`independent_review_required` is exactly
["raw_evidence_linkage", "actual_model_and_tool_policy", "screenshots_and_window_ownership"].
coverage_limitations copies manifest. No `model_verified` output field.

by_action maps each seven action to {planned_eligible, reported_first_matches,
quota:10}; by_variant maps `suite/case_id/variant` to {planned_slots,
reported_first_matches}. slots preserves manifest order, each exactly
{slot_id, first_state, first_record_id, retry_record_ids, reported_first_match}.
first_state: missing if attempt1 absent, conflict if conflicted, else record state.
first_record_id null for missing/conflict; retries sorted by attempt then record ID.
duplicates is sorted list of duplicate record IDs (one per repeated ID);
conflicts sorted unique involved slot IDs. Retain all first failures and retries.
Only eligible, matched attempt1 with action matching target and complete conflict-free
binding contributes one candidate. Action mismatch is a valid noncandidate claim.
Retries never become first, overwrite failure, or add candidates. Noninput slots,
failed/unknown/blocked/rejected/zero never contribute, even if supplied matched.
candidate_count_met iff every action's reported_first_matches >=10.
Synthetic fully matched records may meet that numeric condition, but GUI and action
trial gate flags ALWAYS remain false. Extra fields such as gui_verified/model_verified
are rejected; evidence refs/hashes cannot bypass independent review.
